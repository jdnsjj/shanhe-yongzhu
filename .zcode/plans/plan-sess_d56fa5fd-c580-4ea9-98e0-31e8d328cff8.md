## 开始界面实现方案

1. **启动状态调整**
   - 修改 `scripts/main.gd` 的 `_ready()` 启动顺序：先初始化字体、背景纹理、音效和 UI 资源，再显示开始界面；不立即让地图和主界面成为玩家第一眼看到的内容。
   - 保留 `GameState.new_game()` 的默认初始化，不改变季度规则、AI 约束和存档数据。
   - 根据 `gs.has_save()` 动态决定“继续前局”按钮是否可用。

2. **新增开始界面层**
   - 在 `main.gd` 中增加独立的开始界面构建函数，使用全屏宣纸/舆图背景、半透明纸面区域、墨色标题和朱印色强调。
   - 首屏内容包括：
     - 游戏名称“山河永驻”；
     - 历史开局副题“天启帝崩，信王继统 · 崇祯元年”；
     - 简短的季度制提示“一个回合，一个季度”；
     - “开始新局”主按钮；
     - 有存档时显示“继续前局”；
     - “退出游戏”按钮。
   - 不增加营销式长篇说明，保持历史模拟器的工作台风格。

3. **进入游戏逻辑**
   - 新增 `_enter_game(new_game: bool)`：
     - 新局时调用 `gs.new_game()` 并保存；
     - 继续时调用 `gs.load_game()`；
     - 清除开始界面层；
     - 构建或显示现有地图、顶部状态、右侧菜单、底部行动按钮和信息面板；
     - 调用 `_connect_signals()`、`_refresh_all()`，确保信号只连接一次。
   - 将现有 `_build_ui()` 拆成“基础背景/地图”和“游戏 HUD”两个阶段，避免开始界面和游戏 HUD 同时存在。
   - 将存档询问从 `_ready()` 移除，开始界面直接承担继续/新局选择；已有存档时不再额外弹出旧的二次询问。

4. **兼容现有交互**
   - 保留 `_ask_continue()` 作为旧调用兼容函数，但正式启动流程不再使用它。
   - 确保开始界面按钮不会触发地图点击、季度按钮或 AI 请求。
   - 使用现有 `_paper_layer()`、`_ink_button()`、`_ink_label()` 和 `overlay_layer` 管理视觉与层级，避免新增独立场景文件。

5. **验证**
   - 用 `D:\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64_console.exe` 无头启动项目，确认开始界面路径无脚本编译错误。
   - 运行 `tools/test_sim.gd`，确认季度无 API Key 契约不受影响。
   - 若环境支持 GUI，再检查开始界面按钮进入新局、继续存档和退出按钮的可用状态。
