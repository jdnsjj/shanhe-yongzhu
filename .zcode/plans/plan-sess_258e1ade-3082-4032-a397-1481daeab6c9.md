## 修复方案（继续保持 Python 与正式项目隔离）

### 1. 先统一地图数据模型
当前 `scripts/map_canvas.gd` 和 Shader 只认识 `gs.provinces` 的 17 个明朝省份，`province_colors.json` 也只有 17 个 ID，所以蒙古、鞑靼、后金和其他国家即使存在于旧世界数据，也不会成为可渲染、可命中的地块。

新增统一的 `data/world_regions.json`，为每个外部区域保存：

- `id`、中文名、势力归属、是否可点击、显示颜色
- 投影后的多边形环
- 标签锚点、角度、字号和逐字偏移

首批区域包括：蒙古、鞑靼、后金/满洲、朝鲜、日本、安南、老挝、暹罗、缅甸、柬埔寨、吕宋。辽东继续沿用现有玩法省份，满洲作为其北侧/东北侧独立外部区域，避免把“后金”只显示成一条文字。

“鞑靼”不再只做文字注记，而是定义为塞北西部独立区域；蒙古定义为其北部/西北部区域。两块使用不同填色、边界和标签，保证舆图上能看出地块差异。

### 2. 用 C# 完整替代旧 Python 地图构建流程
扩充现有 `tools/MapBuilder/`，仍然是独立 .NET 8 控制台工具，游戏运行时不依赖 .NET。

- 使用 `System.Text.Json` 读取现有 GeoJSON/TopoJSON。
- 在 C# 内实现 TopoJSON arc 解码、墨卡托投影、几何裁切/合并和多边形简化；不调用 Python。
- 使用 `NetTopologySuite` 做有效性修复、union、相交和边界运算；使用 `SixLabors.ImageSharp` 输出 PNG。
- 输出并覆盖：
  - `assets/map/map_base.png`
  - `assets/map/map_lines.png`
  - `assets/map/province_id.png`
  - `data/province_colors.json`
  - `data/world_regions.json`
  - `data/label_layout.json`

### 3. 单独重建海岸线层
海岸线不再从“明朝省界 + 全部国家 + 外围补全几何”的混合 union 中取 exterior。

C# 构建器分成三类几何：

- `land_union`：所有陆地合并，只用于陆地填色和海岸线。
- `administrative_boundaries`：明朝省界、外部国家边界，只用于内部边界线。
- `coastline`：只绘制 `land_union` 的外边界，不画国家内部边界、不画重复 buffer 轮廓。

海岸线使用独立的细墨线和极弱外晕两层，统一投影后再栅格化，避免当前因经纬度 union、重叠 polygon 和多重描边造成的断线、错线、内陆线假冒海岸线问题。

### 4. 扩展 Godot 地图运行时
修改 `scripts/map_canvas.gd` 和 `shaders/map_overlay.gdshader`：

- 继续保留预渲染贴图方案，不退回运行时绘制复杂多边形，保证性能。
- 将 ID/颜色表从固定 17 个省扩展为“17 省 + world regions”，上限固定为 32 或拆成两个小批次，避免动态数组和 shader 分支失控。
- 外部区域静态显示势力色；悬停/点击可以显示区域名和“外部势力”信息，但不影响现有内政行动。
- 蒙古、鞑靼、后金/满洲、朝鲜、日本等区域都能命中并高亮。
- 移除旧 `map_labels.png` 的运行时依赖，省名和外部区域名全部用 Godot 字体实时绘制，避免位图放大后模糊。
- 地图绘制顺序固定为：底图 → 势力填色 → 海岸线/行政边界 → 静态标签 → 动态悬浮信息，确保海岸线不会盖住文字。

### 5. 重做标签布局，不再“只缩小字号”
标签布局由 C# 生成数据，Godot 做最后一层字体尺寸适配：

- 以投影后的真实区域 polygon 为约束，而不是只看经度 bbox。
- 对候选锚点、角度和字号进行搜索，检查实际文字包围盒/四角是否落在对应区域内。
- 标签位置错误时优先移动锚点或旋转，不直接一路缩小到模糊的小字。
- 甘肃采用逐字布局：沿西北到东南方向放置“甘”，“肃”单字再轻微偏转；使用实际字形包围盒检查，不让旋转后的字越界。
- 蒙古、鞑靼、后金/满洲使用更大、更不透明的区域标签，与国家边界保持安全间距。
- 所有标签文字使用完全不透明墨色，浅色 halo 只作为 1px 边缘衬，不再使用整体半透明字。

### 6. 重做 UI 资源与显示方式
当前 UI 的问题不只是抠图，`StyleBoxTexture` 在九宫格拉伸带来的软边和半透明纸底也会让按钮看起来脏、丑。

- 扩充 `tools/UiAssetPrep/` 的 C# 处理：边缘连通抠图、抗锯齿 alpha、四角 alpha 校验、残留背景比例校验；失败的素材直接报错，不静默输出。
- 正式运行时的普通按钮和资源牌改用 Godot `StyleBoxFlat`：宣纸色、1px 墨线、最多 2px 圆角、小朱印导视。AI 底板只保留给弹窗或确实需要纹理的组件，避免九宫格把边缘拉糊。
- 图标统一为固定方形容器、统一内边距和像素尺寸；诏书印与按钮文本保留明确左侧间距，不再重叠。
- 所有 UI 控件禁止使用整体 alpha 作为常态显示；只有 toast/遮罩使用动画透明度。
- toast 使用独立宣纸底板，放在顶部牌下方安全区；选省面板和底部按钮保持互不覆盖。

### 7. 解决字体“半透明、模糊”
- 统一普通 Label、Button、RichTextLabel、地图标签的字体资源和颜色，文字主体 alpha 固定为 1.0。
- UI 字号按实际窗口比例重新标定；地图动态信息从当前 13px 提高到能在 1280×720 窗口保持清晰的整数逻辑字号。
- 对重要标题、地图标签和按钮文字加极细墨色描边，不再用低 alpha 浅色阴影模拟清晰度。
- 优先使用项目内可打包的中文字体文件（推荐思源宋体 SC 或霞鹜文楷），避免不同电脑的 `SystemFont` fallback 产生字形和抗锯齿差异。字体文件放入 `assets/fonts/`，不需要依赖系统安装。
- 这一步不需要额外安装 Python；C# NuGet 包由 .NET 自动恢复。当前机器已有 .NET SDK 8.0.424，Godot 4.7.2 继续使用标准版即可。

### 8. 验证标准
完成后只执行 Godot 和 C# 命令：

1. 编译 `MapBuilder` 与 `UiAssetPrep`，从项目外目录运行一次，确认没有工作目录依赖。
2. 生成地图资源，检查海岸线只出现在陆海交界，内部行政线不被误画成海岸线。
3. 检查蒙古、鞑靼、后金/满洲及其他国家都有实际填色、多边形、边界和可命中标签。
4. 检查 17 个明朝省名和外部区域标签没有越界、重叠或缩小到不可读；重点验收甘肃逐字斜排。
5. 检查所有 UI PNG 为 RGBA、四角透明、无残留矩形底；普通按钮使用清晰的程序化纸面样式。
6. 执行 Godot `--headless --import` 和无头回归，确认没有脚本错误。
7. 启动游戏做全景、悬停蒙古/鞑靼/后金、选省面板、toast、政令弹窗和诏书弹窗截图，按“海岸线正确、地块完整、字不糊、UI 不脏不挡字”作为验收门槛。

正式项目仍不调用 Python；旧脚本继续留在 `tools/legacy-python/` 仅作历史参考。
